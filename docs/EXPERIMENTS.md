# Эксперименты и воспроизводимость

В комплекте пять результатов разработки одного Task Tracker. Четыре современных ветки используют одинаковые бриф, интерфейсы данных, начальные данные и девять исходных приёмочных тестов. Старый Qwen Coder — отдельный более ранний опыт с другим объёмом итераций.

| Ветка | Модель | Спецификация | API-запросы | Вход | Выход | Расчёт стоимости |
|---|---|---|---:|---:|---:|---:|
| Sonnet + OpenSpec | anthropic/claude-sonnet-5.5 | да | 172 | 5 133 164 | 238 116 | $12,65 |
| Sonnet, прямые задания | anthropic/claude-sonnet-5.5 | нет | 131 | 2 697 063 | 174 123 | $7,14 |
| Старый Qwen Coder | qwen/qwen3-coder | нет | 544 | 26 928 080 | 238 022 | $17,30 |
| Qwen, прямые задания | qwen/qwen3.8-flash | нет | 164 | 3 623 308 | 153 495 | $0,62 |
| Qwen + OpenSpec | qwen/qwen3.8-flash | да | 268 | 8 556 572 | 200 858 | $1,38 |

Сумма считается по полному объёму входа и выхода всех запросов. Тарифы на момент записи: Sonnet — $2 / $10 за миллион входных / выходных токенов; Qwen Flash — $0,15 / $0,47. Архивный Coder использовал несколько провайдеров; их расчёты сохранены отдельно. Одна цифра из фактического списания с кэшированием не используется вместо стоимости полного объёма.

## Что хранится

`experiments/<ветка>/recording.json` связывает роли, задания, времена, метрики и чекпоинты. `api-requests.jsonl`, если он доступен для ветки, содержит очищенную историю измерений запросов. Заголовки авторизации, ключи, cookies, балансы и частные записи созвонов исключены. Код каждого этапа находится в `checkpoints/<id>/code/`, скриншоты — рядом.

Полный порядок:

1. Analyst читает бриф, вычисляет контрольные значения и выявляет неоднозначности.
2. В spec-ветке Analyst создаёт proposal, требования с WHEN/THEN-сценариями, design и tasks.
3. Designer определяет раскладку и состояния интерфейса.
4. Developer реализует `dist/index.html`, `app.js`, `domain.js`, `styles.css`.
5. Tester запускает исходные тесты, проверяет код, фиксирует дефекты. Невыполненная браузерная проверка не объявляется пройденной.
6. Developer исправляет подтверждённые дефекты; Tester повторяет проверку.
7. Analyst возвращает новые подтверждённые правила в спецификацию.

У каждой роли своя инструкция и границы записи. Настройки находятся в `templates/<ветка>/opencode.json`. Современные ветки не задают температуру; численное значение провайдера в измерениях не фиксировалось. Лимиты — 25 шагов для Analyst, Designer, Tester и 55 для Developer.

## Что изменено после исходной записи

Сохранены отдельные подготовленные этапы `qspec-ui-12` и `sdd-ui-20`. Они применяют один общий визуальный контракт к двум spec-веткам: панель, шапка, метрики, сотрудники, фильтры, доска, форма и адаптивность. Эти изменения не выдаются за дополнительные API-вызовы моделей. Исходные `qspec-11` и `sdd-19` сохранены, доступны из карточек результатов и не перезаписаны.

В `ui/spec-ui-contract.md` лежит общий план. В новых API-шаблонах он добавлен заранее, чтобы его можно было использовать в собственном эксперименте. Простое сходство двух доработанных интерфейсов не доказывает самостоятельного выигрыша модели.

Некоторые диагностические вставки в промптах переведены на русский для показа. `originalPrompt` сохраняет оригинал; файлы и ответы исходной записи от перевода не меняются. Новый платный запуск с переводом может дать другой результат.

## Подтверждённый результат сравнения

В одинаковом дополнительном наборе из 18 проверок Qwen без спецификации прошёл 16, Qwen с OpenSpec после дополнительной приёмки — 18. Отличия: отклонение некорректной даты задачи и неверного ключа недели доступности в сохранённых данных. Девять исходных доменных тестов проходят в обеих ветках.

Новый вариант потребовал больше запросов и машинного времени. Ветка проходила дополнительный цикл проверки и исправлений, поэтому из этих записей нельзя выделить чистый причинный эффект спецификации при одинаковом бюджете. Историческая цена и длительность сохранены без искусственного преимущества.

Повторить общий набор:

```powershell
node experiments/compare-domain.mjs direct=checkpoints/flash-13/code spec=checkpoints/qspec-11/code
```

Скрипт сохраняет `experiments/domain-comparison.json`. Для проверки нового оформления используйте `spec=checkpoints/qspec-ui-12/code`; доменная логика в нём совпадает с исходной.

## Повторить показ или запустить заново

- Повторить показ буквально: `START-WINDOWS.cmd`, затем кнопки вставки и отправки в двух чатах. API не используется, код берётся из проверенных снимков.
- Провести новый эксперимент: создайте отдельный проект по [LIVE-API.md](LIVE-API.md), подключите собственный API и выполняйте задания. Сохранённые метрики нельзя переносить на новый запуск без замера.
- Проверить целостность: `npm run check` и `npm test`.
- Проверить настоящее подключение OpenCode к локальной записи: после запуска `npm run smoke`. Команда продвигает левую ветку на один сохранённый шаг.

## Время

Главная таблица показывает машинное время всех завершённых этапов, включая ранние попытки. Токены/с — выходные токены, делённые на время API-запросов с ожиданием первого ответа. Активное время человека отдельно не замерено. Остаток общего времени с паузами не является достоверным замером человеческого труда.
