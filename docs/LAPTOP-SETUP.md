# Запуск на другом ноутбуке

## Что нужно

Проверенный вариант — Windows 10/11, обычный браузер и Node.js 22.14+ или 24 LTS. Отдельный OpenCode, Python, Docker, Git и API-ключ для воспроизведения не нужны. Свободное место требуется для снимков и установленного OpenCode; оставьте хотя бы 1 ГБ.

Первичная установка зависимостей требует доступа к npm. Сам показ готовых этапов и приложений использует localhost. Корпоративная политика ноутбука может ограничивать установку Node.js или запуск локальных серверов; это нужно проверить на целевом устройстве.

## Установка без терминала

1. На GitHub нажмите Code → Download ZIP.
2. Распакуйте архив, например в Documents/OpenCode Lab. Не запускайте файлы прямо из ZIP.
3. Установите Node.js с https://nodejs.org/en/download, если его нет.
4. Дважды нажмите INSTALL-WINDOWS.cmd. Дождитесь завершения установки и проверок.
5. Дважды нажмите START-WINDOWS.cmd.
6. Откроется главный экран http://127.0.0.1:4201/welcome. Вверху — PDF, ниже — все пять результатов.

Для последующих запусков нужен только START-WINDOWS.cmd.

## Установка через терминал

```powershell
git clone https://github.com/jabrailkhalil/opencode-agent-lab.git
cd opencode-agent-lab
npm ci
npm run check
npm test
npm run doctor -- --json
npm start -- --open
```

OpenCode устанавливается локально из package-lock.json. Версии выбраны для совместимости автоподстановки; глобальная установка не требуется.

## Что должно открыться

| Окно | Адрес | Что находится |
|---|---|---|
| Главная | http://127.0.0.1:4201/welcome | PDF и пять реализаций |
| Пульт со спецификацией | http://127.0.0.1:4201/?profile=claude#intro | Qwen + OpenSpec по умолчанию |
| Пульт с прямыми заданиями | http://127.0.0.1:4201/?profile=qwen#intro | Qwen без OpenSpec по умолчанию |
| Два чата | http://127.0.0.1:4201/parallel | Вставка и отправка заданий |
| Выводы | http://127.0.0.1:4201/comparison#conclusion | Метрики всех пяти прогонов |
| PDF | http://127.0.0.1:4201/guide.pdf | Подробная пошаговая инструкция |

Внутреннее имя profile=claude историческое: оно обозначает левую рабочую папку. Название модели определяется выбранной веткой, и по умолчанию в левом окне работает запись Qwen со спецификацией.

## Проверка перед передачей

1. `npm run check` — 116 чекпоинтов, контрольные суммы, конфиги и комплектность.
2. `npm test` — структура пяти результатов, расчёт метрик и сохранность исходной логики.
3. `npm run doctor -- --json` — ОС, версии, зависимости и порты.
4. В браузере открыть PDF, пять приложений и метрики.
5. В двойном окне нажать «Вставить оба промпта». Должны появиться тексты и нужные роли.
6. `npm run smoke` — проверка реального OpenCode через локальную запись, без расходов API.
7. `npm stop`, затем `npm start -- --open` — вернуть чистый старт для пользователя.

## Если не запускается

- Node.js не найден: установить официальный Node.js и открыть новое окно терминала.
- npm ci не скачивает пакеты: проверить доступ к registry.npmjs.org и ограничения сети. Не отключать проверки TLS.
- Порт занят: doctor покажет номера. Если запущена эта же копия, выполнить npm stop. Для чужого сервиса выбрать согласованное время или окружение, не завершать его вслепую.
- Кнопка вставки недоступна: дождаться загрузки обоих чатов, нажать ↻, затем повторить вставку.
- Сервис остановился: логи находятся в .runtime/logs/.

## Остановка и сброс

`npm stop` останавливает проверенные процессы этой копии. Следующий `START-WINDOWS.cmd` создаёт чистые рабочие папки. Предыдущие версии сохраняются в .runtime/previous-workspaces/.

macOS/Linux в этот комплект не входят как проверенные платформы. Агент на другом устройстве должен отдельно проверить двоичный файл OpenCode, лаунчер, открытие браузера и остановку процессов; нельзя считать такой перенос готовым только по наличию Node.js.
