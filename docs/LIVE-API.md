# Новый API-прогон

Сохранённое воспроизведение и новый эксперимент — разные режимы. Для нового запуска не меняйте папки `.runtime/workspaces`: создайте отдельный проект из шаблона.

```powershell
npm run api:project -- qwen-spec
```

Доступные варианты:

- `qwen-spec` — Qwen 3.8 Flash + OpenSpec;
- `qwen-direct` — Qwen 3.8 Flash, прямые задания;
- `sonnet-spec` — Sonnet 5.5 + OpenSpec;
- `sonnet-direct` — Sonnet 5.5, прямые задания.

Команда печатает путь. Добавьте эту папку как проект в OpenCode, откройте **Settings → Providers**, подключите OpenRouter или прямого провайдера и выберите модель, которая доступна вашему аккаунту. Ключ хранится в хранилище OpenCode; в проект его записывать не нужно.

В конфигурациях есть четыре роли и их границы:

| Роль | Результат | Разрешённая запись | Лимит |
|---|---|---|---:|
| Analyst | анализ и спецификация | `reports/**`, для spec-ветки `openspec/**` | 25 |
| Designer | план и ревью UI | отчёты дизайна, `design.md` | 25 |
| Developer | приложение и исправления | `dist/**`, отчёты, `tasks.md` | 55 |
| Tester | дефекты и проверка | QA-отчёт и дополнительные агентские тесты | 25 |

Доступ к другим папкам, вызов подагентов, web search и изменение исходных приёмочных тестов запрещены. Температура специально не задана: провайдер использует своё значение по умолчанию. Так конфигурация переносится между моделями без придуманного числового параметра.

Промпты по порядку находятся в `prompts.txt`. В spec-ветках после создания артефактов запустите `npm run spec:validate`, а после реализации — `npm test`. Браузерную приёмку выполняйте отдельно: зелёные доменные тесты не подтверждают адаптивность, фокус, drag-and-drop и внешний вид.

Новый запуск расходует API и может дать другой код, время и цену. Для честного сравнения сохраняйте полные входные и выходные токены каждого запроса и отдельно считайте цену без скидки кэша.
