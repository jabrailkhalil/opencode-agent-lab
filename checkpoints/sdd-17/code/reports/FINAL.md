## 4. Открытые замечания и ограничения
Блокирующих ошибок QA и дизайн-ревью не нашли. Исправлялись ли пункты после ревью, в отчётах не сказано: считать их открытыми.

**Средняя важность (дизайн-ревью, по коду):**
- №1 nowrap у кнопки сброса перебивает перенос текста; возможен выход текста за рамку.
- №2 порог 3 колонок доски на 992 даёт ≈229 px на колонку (<240 по плану), только диапазон 992–1023.
- №3 `overflow-x:hidden` скрывает переполнение (см. 3.1).
- №4 у `#confirm-text` нет `overflow-wrap`: длинное название выйдет за 390 px.
- №5 (= QA O1) фокус не возвращается на вызвавший элемент после закрытия формы, подтверждения, предпросмотра: падает на `body`. Это ухудшает клавиатурную навигацию (п. 11).
- №6 ошибка формы может оказаться ниже экрана на 390 px; поля не связаны с `task-error` через `aria-describedby`.

**Низкая важность / информационные:**
- QA O2: `validateTask` принимает массив в `week` при прямом вызове API (из UI недостижимо).
- QA O3: `isValidState` принимает `employees: []`; spec ровно четырёх сотрудников не требует.
- Выбранная неделя не сохраняется: после перезагрузки всегда 2026-09-28 (spec не требует).
- В виде «По сотрудникам» карточки `draggable`, но зон сброса нет.
- Для доступности `capacity=0` и 0 ч: текст «нет доступности» сочетается с бейджем «В пределах доступности».
- Отклонения от плана: `reset-demo` один и всегда в шапке; пустая неделя показывает блок над тремя колонками; плашка подтверждения не рядом с карточкой; в карточке не виден ID; `h3` после `h1`.
- Из-за `type=text` в поле оценки (допускает запятую) проверка только прикладная.
- Новая задача на другую неделю переключает просмотр на её неделю (решение разработчика).
- У боковой панели нет `overflow-y:auto`, возможна недоступность нижней кнопки при малой высоте окна.
