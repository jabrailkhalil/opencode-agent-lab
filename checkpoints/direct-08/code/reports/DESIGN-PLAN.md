# Дизайн-план «Поток» (для разработчика)

Основа: docs/BRIEF.md, INTERFACES.md, DESIGN-REFERENCE.md, reports/ANALYSIS.md. Код не писался, браузер не использовался: всё ниже — требования, не результат визуальной проверки.

## 1. Раскладка

Токены: акцент #206bc4, текст #182433, фон #f6f7f9, границы #e6e8ec, ошибка #d63939, готово #2fb344. Только классы Tabler плюс малый styles.css; без внешних шрифтов и иконок.

Сверху вниз (`data-testid="app"` — корень):
1. **Шапка** «План команды»: слева заголовок и метка недели; справа «Новая задача» (`new-task`, primary), «Предложить распределение» (`propose-plan`), «Восстановить пример» (`reset-demo`, вторичная).
2. **Панель недели**: `prev-week` · `current-week` (кнопка с «28 сен – 4 окт 2026» и ISO `2026-09-28`) · `next-week`.
3. **Сводка недели** (4 метрики): задач всего, активных (7 / 70 ч), всего часов (80), без ответственного (1 / 4 ч). Значения считаются из данных.
4. **Панель инструментов**: `search`, `filter-assignee`, переключатель видов `view-board` / `view-employees` (сегмент btn-group, `aria-pressed`).
5. **Рабочая зона** — два блока: основной (доска или «по сотрудникам») и **боковая панель «Команда»** с четырьмя карточками сотрудников. Панель видна в обоих видах и не зависит от поиска/фильтра.

Сетка рабочей зоны: ≥1200 px — `основной | панель 320 px` (панель sticky). <1200 px — панель **над** основным блоком в сетке `auto-fit` (4/2/1 карточек в ряд, см. п. 6).
Предупреждения (повреждённое хранилище, задача ушла с недели) — `alert` под шапкой, закрываемые, не сдвигают форму.
Подтверждения (удаление, reset-demo) и форма задачи — модальные окна на странице (`confirm-ok`/`confirm-cancel`), не `window.confirm`.

## 2. Нагрузка и прогресс

Два **разных** показателя в каждой карточке сотрудника (`employee-<id>`), разные блоки, разные подписи, разные цвета; не объединять в одну полосу.

- **Загрузка** (`load-<id>`): подпись «Загрузка (активные часы)», строка «32 / 24 ч · 133%», бейдж перегрузки «Перегрузка +8 ч». Полоса: min(percent,100)%; синяя ≤100, красная при перегрузе. Перегрузка — всегда число и слово (не только цвет); при 0 бейдж «Без перегрузки» серый/зелёный текстом. `percent === null` → «нет доступности», при активных часах — «Перегрузка +N ч».
- **Прогресс** (`progress-<id>`): подпись «Прогресс (выполнено часов)», «6 / 14 ч · 43%». Полоса зелёная #2fb344. Нет назначенных часов → «0%» и «нет назначенных часов», без NaN/Infinity.
- **Доступность** (`capacity-<id>`): number-input 0–168, шаг 0,5, подпись «Доступно, ч на неделю» (label for). Сохранение на change/blur; неверное значение — сообщение под полем (`role=alert`), прежнее значение возвращается.
- Порядок в карточке: имя → доступность → загрузка → прогресс. Выполненные не занимают доступность — это поясняет мелкая подпись у загрузки: «без выполненных».
- Группа «Без ответственного» (часы без владельца) — отдельная строка под карточками, без полос и без доступности.
- Доску и вид «по сотрудникам» питают одни данные; рендерится только активный вид, чтобы не дублировать `task-TASK-*`. В виде «по сотрудникам» заголовок группы повторяет «32 / 24 ч · +8 ч» кратко, полные показатели остаются в боковой панели.
- Поиск/фильтр скрывают карточки задач, но не меняют метрики; рядом с поиском подпись «Метрики считаются по всем задачам недели».

## 3. Форма и ошибки

Модальное окно `task-form` (`novalidate`), заголовок «Новая задача» / «Правка TASK-101». Поля в порядке: название (`task-title`, счётчик x/140), описание (`task-description`, 4 строки, x/1000), ответственный (`task-assignee`, «Без ответственного» = пустое значение), оценка (`task-hours`, шаг 0,5), статус (`task-status`: Новая/В работе/Готово), неделя (`task-week`, подсказка «Понедельник»). Каждое поле — видимый `label for`; на 768+ пары ответственный/статус и оценка/неделя в две колонки, на 390 одна колонка.

- Ошибка `task-error` (`role="alert"`) — красный alert **внутри** формы над кнопками, а не toast. Названия поля и причина: «Название: от 1 до 140 символов». При ошибке поле получает `is-invalid`, `aria-invalid`, `aria-describedby`; фокус на первое неверное поле.
- Значения при ошибке **не сбрасываются**, форма не закрывается. Ошибка исчезает при правке или успешном сохранении.
- Кнопки: «Сохранить» (`task-save`, primary) и «Отмена» (`task-cancel`); в правке слева ещё «Удалить» (красная outline, через подтверждение). Esc и фон = отмена; фокус возвращается на вызвавшую кнопку, внутри окна фокус зациклен.
- Форма на 390: на всю ширину, тело скроллится внутри окна, кнопки внизу в столбик на всю ширину.
- Поле доступности: проверка на месте; ошибки формы и доступности не смешиваются.

## 4. Пустые состояния

- Колонка доски без задач: пунктирная зона «Нет задач. Перетащите карточку сюда» (зона всё равно `column-*`, сохраняет высоту ≥ 96 px как цель drop). Подсветка при dragover; клавиатурная замена — `task-status` в форме.
- Поиск/фильтр ничего не нашли: над доской строка «Ничего не найдено по запросу…» + «Сбросить поиск»; колонки показывают пустое состояние. Метрики не меняются.
- Сотрудник без задач в виде «по сотрудникам»: «На этой неделе задач нет». Нулевая доступность: «Нет доступности» вместо процента.
- Неделя без задач вовсе: общий блок «На этой неделе задач нет» + «Создать задачу».
- Нет изменений от плана: «План совпадает с текущим — менять нечего», «Применить» отключена.
- Повреждённое хранилище: предупреждение «Данные повреждены, загружен учебный пример».

## 5. Предпросмотр плана

- «Предложить распределение» открывает `plan-preview` — панель над рабочей зоной (не модальная, чтобы метрики оставались видны). Исходные данные и метрики не меняются, пока не нажато `plan-apply`.
- Содержимое: заголовок «Предпросмотр — изменения не применены»; таблица «Задача · Было → Станет · Часы» (только изменившиеся, остальные счётчиком «ещё N без изменений»); итог «Не помещается: N ч — остаются без ответственного»; блок «Нагрузка после применения» по сотрудникам («Анна 24 / 24 ч · без перегрузки»), рядом текущая.
- Кнопки: «Применить» (`plan-apply`, primary), «Отмена» (`plan-cancel`). Выполненные задачи в плане не показываются; подпись «Выполненные и другие недели не затрагиваются».
- Правка задач/доступности, смена недели — отмена предпросмотра с уведомлением. Esc в панели = отмена.
- На 390 таблица превращается в список строк «Название / Было → Станет»; кнопки в столбик на всю ширину.

## 6. Адаптивность: 390 / 768 / 1100 / 1280

Правило: у страницы нет горизонтального скролла (`overflow-x` не скрывать, а устранять причины: `min-width:0` у grid-детей, `overflow-wrap:anywhere`). **Длинные кнопки («Предложить распределение», «Восстановить пример») не помещать в четыре колонки рядом с боковой панелью**: действия идут в `flex-wrap` строке, каждая кнопка в естественной ширине (`white-space:nowrap` лишь при ширине ≥ 768, иначе перенос текста допустим), без сетки 4×1.

| Ширина | Раскладка |
|---|---|
| **390** | Одна колонка. Шапка: заголовок, затем действия столбиком на всю ширину («Новая задача» первой). Неделя: `current-week` на всю строку, ‹ › по бокам. Сводка 2×2. Инструменты: поиск, фильтр, переключатель видов — по строке. «Команда» над доской: карточки в 1 колонку, доступность и две полосы внутри. Доска — колонки друг под другом; DnD работает, клавиатурная правка остаётся основной. Форма/модалки на всю ширину. |
| **768** | Одна колонка. Действия в wrap-строке. Сводка 4 в ряд (или 2×2, если тесно). Команда — сетка 2×2. Доска 3 колонки `minmax(220px,1fr)`, карточки компактны; заголовки колонок не обрезаются. Поиск и фильтр в одной строке, виды справа. |
| **1100** | Всё ещё одна колонка основной зоны: «Команда» — 4 карточки в ряд (`auto-fit minmax(240px,1fr)`), ниже доска на всю ширину, 3 колонки по ~340 px. Боковой панели рядом нет — так кнопки и колонки не сжимаются. |
| **1280** | Двухколоночно: основной блок + панель «Команда» 320 px справа (sticky), карточки панели в 1 колонку. Доска 3 колонки ~280 px. Действия шапки — одна wrap-строка над обоими блоками, не внутри узкого столбца. |

Переключение на боковую панель — медиа-запрос `min-width:1200px`. Внутри карточки задачи кнопки «Изменить»/«Удалить» wrap; название `overflow-wrap:anywhere`. Таблица/список «по сотрудникам» на <768 — карточки-блоки, без горизонтальной таблицы.

## 7. Доступность и стиль

- Все поля с видимыми `label for`; интерактивные элементы — настоящие `button`/`input`/`select`; видимый focus-ring (акцент). Tab-порядок = визуальный. Esc закрывает модалки/предпросмотр. Состояния не только цветом (текст «Перегрузка», «Готово»).
- Тосты/ошибки: `role="alert"`; обновление метрик — `aria-live="polite"` у сводки.
- Цвета только из токенов п. 1; контраст текста ≥ 4,5:1. Карточки Tabler (`card`, `badge`, `progress`, `btn`, `form-control`, `form-select`), радиус и тени по умолчанию.
- Статусные бейджи: Новая — серый, В работе — синий, Готово — зелёный.
