## 1. Каркас и раскладка

- Стиль Tabler 1.6.1 (локальный), светлая навигация; фон #f6f7f9, текст #182433,
  границы #e6e8ec, акцент #206bc4, ошибка #d63939, успех #2fb344.
- Порядок сверху вниз: navbar («Поток») → page-header «План команды» +
  недельная навигация → toolbar представлений → строка действий → метрики
  недели → основной блок (board | employees-view) → инлайн-форма → preview.
- Боковой панели НЕТ. Длинные кнопки («Новая задача», «Предложить
  распределение», «Восстановить учебный пример») НЕ сжимать в 4 колонки рядом
  с sidebar: они в отдельной строке `d-flex flex-wrap gap-2`, на ≤768 —
  колонкой на всю ширину, полный текст без truncate.
- Сетка: Tabler-контейнер, контент ≤1200 px; колонки канбана — три равные
  зоны column-todo/doing/done.

## 2. Недельные метрики (отдельно от действий)

- Четыре карточки показаний (col-6 col-lg-3 — это про ЦИФРЫ, не про кнопки):
  «Задач всего», «Активные часы», «Доступно часов», «Перегрузка, ч».
- Перегрузка: число + подпись «перегрузка +8 ч» цветом #d63939; при 0 — «0 ч».
- Метрики считаются по всем задачам недели; поиск/фильтр их НЕ пересчитывают
  (подпись «по всем задачам недели» в header блока).

## 3. Нагрузка отдельно от прогресса

- В employees-view каждая employee-<id> — карточка/строка с ДВУМЯ независимыми
  подписанными блоками, никогда не одной смесью:
  - «Загрузка» load-<id>: `32/24 ч`, `133%`, `перегрузка +8 ч`;
  - «Прогресс» progress-<id>: `43%` + подпись «выполнено 6 из 14 ч».
- Нагрузка = активные/доступные; прогресс = done/все назначенные недели —
  разные формулировки подписей, чтобы визуально не сливались.
- percent=null → «—» + подпись «нет доступных часов»; progress без часов →
  «0%», никаких NaN/Infinity.
- В board-виде нагрузка не дублируется: краткий чип сотрудника на карточке
  задачи; полное разделение — только в employees-view.

## 4. Форма задачи и ошибки

- task-form — инлайн-панель (card) под toolbar, сворачивается по task-cancel;
  не модалка: на 390 px значения остаются видимыми при прокрутке.
- Поля с label-for: task-title (input), task-description (textarea),
  task-hours (input, шаг 0,5), task-assignee (select: id сотрудников + пустое
  = «Без ответственного»), task-status (select todo/doing/done), task-week
  (input date, понедельник). Две колонки ≥768, одна колонка 390/768.
- task-error — alert alert-danger ВНУТРИ формы, сверху, aria-live=polite;
  текст вида «Укажите название (1–140 символов)». При ошибке форма НЕ
  закрывается и поля НЕ сбрасываются; невалидное поле — красная рамка #d63939.
- Кнопки task-save (primary) / task-cancel — внизу формы, на мобильном
  полноширинные в колонку, на десктопе в строку справа.

## 5. Пустые состояния

- Пустая колонка канбана — пунктирная зона column-* с подписью «Нет задач»
  (зона drop сохраняется).
- Пустая неделя в employees-view — карточка-заглушка «На этой неделе задач
  нет» + кнопка «Новая задача».
- Пустой результат поиска/фильтра — «Ничего не найдено» + подсказка сбросить
  search/filter-assignee; под блоком подпись, что метрики показаны по всем
  задачам недели.
- Недоступность 0 у сотрудника — блок «Загрузка» не исчезает: «— из 0 ч».

## 6. Предпросмотр плана

- propose-plan открывает модалку plan-preview (Tabler modal) поверх затемнения.
- Внутри: по сотрудникам — было/стало (активные часы против доступности);
  отдельно список задач, оставшихся «Без ответственного», и unassignedHours.
- Обязательная подпись: «Это предпросмотр, исходный план не изменён».
- Кнопки в footer: plan-cancel (обычная), plan-apply (primary) — на 390 px
  вертикально полноширинные, на ≥768 в строку. Apply не закрывает превью
  без явного нажатия; cancel ничего не меняет.

## 7. Поведение по ширине

| Ширина | Ключевые решения |
| --- | --- |
| 390 px | 1 колонка; канбан — три зоны вертикально (без horizontal-scroll формы); actions в колонку; метрики col-6 (2×2); таблица сотрудников → карточки; load/progress друг под другом; overflow-x скрыт контентом, не обрезкой данных |
| 768 px | метрики 2×2; actions wrap; board — 3 колонки ≥220 px; форма 2 колонки; employees — строки таблицы, блоки «Загрузка»/«Прогресс» в 2 колонки |
| 1100 px | метрики в 4 карточки (только цифры); board 3 колонки; employees-таблица с capacity-<id> полями 0–168; превью-модалка 600 px |
| 1280 px | контейнер 1200; то же, что 1100, запас по полям; drag-and-drop между колонками без переноса |

Ни на одной ширине показатели нагрузки/прогресса не скрываются (нет
display:none для load-*/progress-*), нет горизонтального переполнения.

## 8. Доступность и клавиатура

- Все действия — реальные <button>; focus-visible #206bc4; tab-order:
  навигация недели → views → actions → метрики → контент → форма.
- Переключение статуса дублируется select в форме (не только drag-and-drop).
- reset-demo — подтверждение через confirm(); текст кнопки полный.
