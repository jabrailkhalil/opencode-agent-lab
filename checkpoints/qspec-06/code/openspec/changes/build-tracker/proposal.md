# Proposal: build-tracker — трекер задач и планировщик нагрузки «Поток»

## Why

Нужен с нуля локальный веб-сервис, объединяющий канбан-трекер задач и недельный
планировщик загрузки четырёх сотрудников. Прежний код запрещён; используется только
локальный CSS Tabler из `dist/vendor/tabler/`. Приёмка фиксируется девятью
заранее написанными тестами `tests/acceptance.test.mjs`, поэтому доменная логика
должна точно соблюдать контракт `docs/INTERFACES.md`.

## What Changes

- Новый модуль `dist/domain.js`: `DEMO_WEEK`, `seedState`, `monday`, `loadFor`,
  `validateTask`, `proposePlan`, `applyPlan`, `isValidState` — чистые функции.
- Новый `dist/app.js`: рендер доски и представления по сотрудникам, форма задачи,
  поиск/фильтр, переключение недель, редактирование доступности, drag-and-drop,
  предпросмотр плана с явным применением, localStorage с защитой от порчи данных.
- Новые `dist/index.html` и `dist/styles.css` на локальном Tabler, адаптивно для
  390/768/1100/1280 px, со всеми `data-testid` из контракта UI.
- Ключевые метрики: нагрузка = активные часы/доступность (percent, overload),
  прогресс = выполненные часы/все назначенные часы недели; нулевая доступность
  даёт `percent = null` без NaN/Infinity.
- Планировщик: `proposePlan` не мутирует состояние, не назначает сверх доступности,
  неприместившиеся активные задачи остаются без ответственного; выполненные задачи
  и чужие недели не трогаются.

## Impact

- Артефакты: `dist/index.html`, `dist/styles.css`, `dist/app.js`, `dist/domain.js`.
- Данные: `docs/seed-state.json` (копия через `seedState()`), localStorage как хранилище.
- Риски: расхождение округления процентов, мутация состояния при предпросмотре,
  регресс адаптивности; покрывается сценариями спеки и тестами.
- Затронутых систем/регрессий вне проекта нет; бэкенда и авторизации нет намеренно.
