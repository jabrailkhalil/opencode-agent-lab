# DEVELOPMENT: build-tracker

Роль: developer. Реализовано по BRIEF, INTERFACES, DESIGN-PLAN и OpenSpec `build-tracker`. Браузер не запускался, сервер не стартовал: визуальная и DOM-проверка не выполнялись.

## Созданные файлы
- `dist/domain.js` — чистая логика: DEMO_WEEK, seedState (встроенная копия seed), monday/addDays (UTC), loadFor, validateTask, isValidState, proposePlan (жадный: крупные задачи первыми, сотруднику с максимальным остатком), applyPlan; плюс STATUSES, STATUS_LABELS, capacityFor.
- `dist/index.html` — каркас: боковая/верхняя панель (виды, reset-demo), неделя, действия, метрики, сотрудники, поиск/фильтр, слоты подтверждения/формы/плана, `board`, `employees-view`.
- `dist/styles.css` — отличия от Tabler: фокус, раскладка, drop-зоны, line-clamp, таблица плана → карточки <768, медиазапросы 576/768/992.
- `dist/app.js` — UI: хранение (`potok.state.v1`, try/catch, откат к seed с `alert-warning`), метрики, карточки сотрудников (load/progress/capacity), доска с DnD, вид по сотрудникам, форма, подтверждения, предпросмотр плана, события.

## Выполнено по брифу (по коду)
1. CRUD задач — форма `task-form`, edit/delete, удаление через встроенное подтверждение.
2. Статусы и доска — три колонки, HTML5 DnD и смена статуса в форме.
3. Вид по сотрудникам и «Без ответственного», те же данные.
4. Поиск/фильтр — только список; метрики и нагрузка считаются по всем задачам недели.
5. Недели prev/next/current, старт 2026-09-28; `capacities` по неделям.
6. Доступность 0–168 шаг 0,5, сохранение на change/blur, ошибка под полем, откат значения.
7. Загрузка/прогресс — раздельные блоки; при capacity=0 «нет доступности», без NaN/Infinity.
8. План: предпросмотр без изменения данных, apply/cancel, устаревает при любом изменении.
9. localStorage, повреждённые данные → seed + уведомление; reset после подтверждения.
10. Валидация формы в `task-error`, форма и значения не сбрасываются, `aria-invalid` + фокус на поле.
11. Адаптив написан (метрики 2→4, карточки 1→2, доска стопкой →3 колонки с 992 px), но не проверен на ширинах.
