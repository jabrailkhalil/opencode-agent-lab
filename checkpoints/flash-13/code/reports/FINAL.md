## 2. Исправленные дефекты (D1–D4)
Все четыре закрыты по коду (DEVELOPMENT.md §«Исправления D1–D4») и зафиксированы в QA-RESULTS.md; внешний прогон BROWSER-RECHECK подтвердил выполнение в браузере.
- **D1** (`#reset-demo` не сбрасывал week/query/filter → пустая доска): исправлено — после `seedState()` сбрасываются week/view/query/filter/plan и поле `#search`. Подтверждено браузером [B]: вернулись 28 сен–4 ок, 9 задач, 7 активных, 70 ч.
- **D2** (`saveCapacity`: пустой ввод молча обнулял доступность + дубль blur → потеря фокуса): исправлено — откат `inp.value = prev`, запись/render только при реальном изменении, возврат фокуса в `capacity-*`, дубль `blur` убран. Основной дефект подтверждён браузером [B] (32/24, 133%, +8 сохраняются). Замечание: текстовая подсказка для пустого поля не появилась — полную UX-приёмку поля не заявляю.
- **D3** (`renderBoard`: при 0 совпадений пропадали колонки → рвался контракт DnD): исправлено — alert рендерится над тремя `column-*`, `reset-filters` обрабатывается раньше поиска `data-id`. Подтверждено браузером [B] («Ничего не найдено» + три пустые колонки).
- **D4** (a11y/клавиатура модалок): исправлено по коду — focus-trap (`dialogKeys`), фон `header/main` в `inert`+`aria-hidden`, возврат фокуса по `data-testid` (в т.ч. после render), Escape закрывает только открытую модалку и чистит editing/plan/confirmCb; убрана запись через оператор запятой в `submitTask`. Подтверждено браузером ЧАСТИЧНО [B]: только диалог задачи (фокус в `task-title`, Shift+Tab→`task-save`, Escape→`new-task`). Полный цикл `plan-modal`/`confirm-modal` браузером не проверялся.

## 3. Оставшиеся ограничения
Поведенческое/визуальное, NOT RUN браузером (не покрыто и BROWSER-RECHECK): полный CRUD на flash-10; реальный drag-and-drop между `column-*`; цикл сохранения и повреждённый `localStorage`; `inert`/Tab-ловушка/возврат фокуса в `plan-modal` и `confirm-modal`; читаемость `load-*`/`progress-*`; визуальная отрисовка `task-error` на flash-10; «единый стиль Tabler»; ширины < 390 px (риск подрезки `minmax(320px,1fr)` при <~352 px).
Отклонения DESIGN-REVIEW §2 (вне D1–D4, разработчиком не заявлены исправленными): таблица сотрудников на ≥1100 (всегда карточки); красный перелив полосы загрузки (перегрузка только текстом); `edit/delete btn-sm` без правила ≥44 px на 390; шапка `plan-preview` без «(M задач)»; самодельный overlay вместо Tabler `.modal`; тавтология «Выполнено часов: N ч»; `filter` не тянется на 100% при 768; container 1068 вместо 1080 при 1100. (Пункт DESIGN-REVIEW «нет focus-trap/возврата фокуса» закрыт кодом D4, но браузером подтверждён лишь частично.)
Прочее: `submitTask` смещает текущую неделю на неделю сохранённой задачи (косметика); нет текстовой подсказки для пустого `capacity-*` (замечание внешнего прогона); `isValidState` не проверяет `version` — миграции ключа `potok-v1-state` нет.
Методологическое: BROWSER-RECHECK — внешний целевой протокол, не полный браузерный набор и не запуск браузера агентом; скриншоты я не просматривал, визуальную проверку не подтверждаю; прогон 19/19 зафиксирован тестером, мной не перепрогонялся; docs, tests/acceptance.test.mjs, dist/vendor не менялись.
