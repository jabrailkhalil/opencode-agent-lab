## Why

Команде из четырёх сотрудников нужен один локальный инструмент, который одновременно ведёт задачи и показывает недельную загрузку людей. Сейчас задачи и доступность живут отдельно. Поэтому перегрузку (например, 32 ч задач при доступных 24 ч) видно только после ручных подсчётов. Нужен работающий статический веб-сервис «Поток» без backend, авторизации и внешних ресурсов. Код предыдущих приложений использовать нельзя, в `dist/` заранее есть только локальный CSS Tabler.

## What Changes

Новая возможность `tracker`, реализуется с нуля в `dist/index.html`, `dist/styles.css`, `dist/app.js`, `dist/domain.js`:

- CRUD задач (название, описание, ответственный или «Без ответственного», оценка в часах, статус, неделя) с прикладной валидацией и формой, которая при ошибке остаётся открытой и не теряет введённых значений.
- Статусы `todo` / `doing` / `done` («Новая», «В работе», «Готово»), доска из трёх колонок с drag-and-drop и смена статуса через форму.
- Второе представление «по сотрудникам» над теми же данными, переключение туда и обратно.
- Поиск по названию/описанию и фильтр по ответственному; они меняют только видимый список карточек, но не недельные метрики.
- Навигация по неделям (предыдущая/следующая/начальная), стартовая неделя `2026-09-28`; задачи и доступность разных недель независимы.
- Недельная доступность 0–168 ч для каждого из четырёх сотрудников.
- Метрики: загрузка (активные часы / доступные часы, округлённый процент, перегрузка в часах) и прогресс (выполненные часы / все назначенные часы недели) с безопасной обработкой нулевых знаменателей (без NaN/Infinity).
- Предложение распределения активных задач: предпросмотр, отмена, явное применение; предпросмотр не меняет план, сверх доступности не назначается, не поместившиеся задачи остаются без ответственного.
- Сохранение в `localStorage`, устойчивость к повреждённым данным, восстановление учебного примера только после подтверждения.
- Адаптивный UI на 390 / 768 / 1100 / 1280 px без горизонтального переполнения, подписанные поля, управление клавиатурой, стиль Tabler.
- Публичный контракт `dist/domain.js` и набор `data-testid` из `docs/INTERFACES.md`.

Вне объёма (Non-goals):

- backend, авторизация, многопользовательская синхронизация, сеть, `npm install`, внешние CDN/шрифты/иконки;
- добавление и удаление сотрудников (их ровно четыре, из seed);
- разбиение одной задачи между несколькими людьми;
- повторяющиеся задачи, дедлайны внутри недели, комментарии, история изменений, undo после применения плана;
- изменение `docs/`, `tests/acceptance.test.mjs` и `dist/vendor/`.

## Capabilities

### New Capabilities
- `tracker`: трекер задач с доской и представлением по сотрудникам, недельная доступность, расчёт нагрузки и прогресса, предложение распределения, хранение состояния, форма и валидация, адаптивный UI и публичный интерфейс домена/тестов.

### Modified Capabilities
- Нет. `openspec/specs/` пуст, существующих спецификаций нет.

## Impact

- Создаваемые файлы: `dist/index.html`, `dist/styles.css`, `dist/app.js`, `dist/domain.js`.
- Не изменяются: `docs/*`, `tests/acceptance.test.mjs`, `dist/vendor/*`.
- Проверка: девять приёмочных тестов `node --test tests/` (импортируют `dist/domain.js` в Node, поэтому домен не должен обращаться к DOM/`localStorage` при импорте) и ручные/браузерные сценарии тестера по `specs/tracker/spec.md`.
- Зависимости: только локальный `dist/vendor/tabler/tabler.min.css`.
- Риски и открытые вопросы перечислены в `design.md` (раздел «Риски и допущения») и в `reports/ANALYSIS.md`.
