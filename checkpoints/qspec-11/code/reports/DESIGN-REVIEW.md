## B. Подтверждённые отклонения/пробелы (требуют правок кода)

1. §1/§7 «на ≤768 actions колонкой на всю ширину»: мобильное правило только у
   `.formbtn` (styles.css:63–67); ряд Действия на 390 остаётся inline-ширины.
2. §5 пустая неделя в employees-view: нет карточки-заглушки «На этой неделе задач
   нет» + кнопка «Новая задача»; лишь text-muted примечание внутри карточки
   сотрудника (app.js:127–129) — на нулевой неделе видны 4 карточки без единого
   пустого состояния.
3. §5 «— из 0 ч»: код печатает `0/0 ч · —` (app.js:123–125) — смысл тот же,
   формулировка расходится.
4. §4 aria-live=polite: task-error имеет одновременно role="alert" и
   aria-live="polite" (index.html:85) — роль подразумевает assertive, явный
   атрибут должен побеждать, но связка неоднозначна; надёжнее region+polite.
5. §8 модал: у plan-modal нет Escape, focus-trap и возврата фокуса на
   propose-plan; после apply/cancel фокус на скрытой кнопке (grep
   `Escape|keydown|trap` по app.js — 0 совпадений).
6. capacity-<id>: onCapacity → полный render() пересоздаёт employees-view; при
   change (Enter/спиннер) активный input уничтожается, фокус в body; второе
   событие (change/blur) прилетает на отсоединённый узел — значение обычно
   сохранено первым, но итог зависит от порядка событий браузера.
7. §7 «768/1100 — таблица сотрудников строками»: всегда карточки `col-12
   col-lg-6`; на 768–991 по одной в ряд. Нагрузка/прогресс видны, структура не
   по плану.
8. §1/§7 контейнер: `container-xl` (шкала Tabler ≈1140 px) против плановых
   1200 px — minor, фактическую ширину смотреть в браузере.
9. maxlength 200/1200 выше лимитов валидации (index.html:89, 97) — осознанно для
   прикладной trim-валидации (INTERFACES:24); лейбл «до 1000 символов» при этом
   не совпадает с фактической блокировкой ввода.
10. Подсказка про метрики при пустом результате внутри .board-empty (app.js:109),
    а план §5 — «подпись под блоком».
