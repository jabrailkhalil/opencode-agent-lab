# DESIGN-PLAN — «Поток»: трекер + планировщик нагрузки

Прочитаны: docs/BRIEF.md, docs/DESIGN-REFERENCE.md, docs/INTERFACES.md, reports/ANALYSIS.md, docs/seed-state.json. Код не писан; визуальное подтверждение — только DOM-ревью в браузере после реализации.

## 1. Общая раскладка
- Структура страницы: светлый navbar (название «Поток») → page-header «План команды» + недельная навигация (prev-week, current-week вида «28 сен — 4 окт 2026», next-week) → toolbar → недельные метрики → содержимое (board или employees) → служебные кнопки.
- Toolbar: search, filter-assignee (select), переключение представлений (view-board / view-employees — btn-group/tab), new-task (кнопка primary).
- Никакого постоянного бокового сайдбара ни на одной ширине: одна колонка Tabler container, метрики и оба представления на всю ширину.
- Недельные метрики: 4 стат-карточки «Всего задач 9», «Активных 7», «Активные часы 70», «Выполнено 10 ч»; считаются по полной неделе, не зависят от поиска/фильтра (ANALYSIS §3.10).

## 2. Нагрузка — отдельно от прогресса
На employee-* (внутри load-*, progress-*, capacity-*):
- Два раздельных подписанных блока, никогда одна общая полоса/число.
- «Загрузка»: `32 ч из 24 ч`, процент `133%`; percent=null (capacity 0) → «—» и подпись «нет доступности», не 0%. Перегрузка — красным числом `+8 ч` со словом «Перегрузка» (#d63939), видна только при overload>0. Полоса загрузки до capacity, перелив — красный участок.
- «Прогресс»: `6 ч из 14 ч` + `43%`, зелёная полоса #2fb344, подпись «Прогресс по выполненным». totalHours=0 → `0%` и «нет назначенных часов» (без NaN).
- capacity-* — number-инпут 0…168 для текущей недели (capacities[week]), сохранение на change/blur.
- ≥1100 px: employees-view — таблица (Сотрудник / Загрузка / Перегрузка / Прогресс / Доступность / Задачи); <1100 — карточки, те же подписанные блоки сохраняются.

## 3. Форма и ошибки
- task-form — модальное окно Tabler (560 px на десктопе, full-screen sheet на 390). Порядок: task-title (input), task-description (textarea rows=3), task-hours (input, 0.5–168, step 0.5), task-assignee (select: «Без ответственного» = пустое значение + 4 id), task-status (select todo/doing/done), task-week (input date, понедельник, по умолчанию текущая неделя).
- У каждого поля label+for, подсказки формата («шаг 0,5 ч»).
- task-error — alert-danger внутри формы над полями, перечисляет все ошибки; проблемные поля `.is-invalid` + aria-describedby, фокус на первое. Значения не сбрасываются, невалидные остаются в полях. task-save primary / task-cancel secondary — в footer справа, с текстовыми подписями.
- delete-* — подтверждение с названием задачи; отмена ничего не меняет. reset-demo — подтверждение перед восстановлением seed.

## 4. Пустые состояния
- Пустая колонка доски: заглушка «Нет задач» + подсказка про drag-and-drop; зона column-* остаётся drop-приёмником.
- Поиск/фильтр без результатов: вместо колонок один alert «Ничего не найдено» с кнопкой сброса; недельные метрики продолжают показывать полную неделю.
- Сотрудник без задач на неделе: загрузка `0 ч из 24 ч` · `0%`, прогресс `0%` · «нет назначенных часов», в списке задач карточки — «Задач нет».
- proposePlan, где всё уже размещено и unassignedHours=0 без изменений: в предпросмотре «Изменений нет», plan-apply не активен.

## 5. Предпросмотр распределения
- propose-plan → модалка plan-preview (исходный план не меняется до plan-apply): шапка-итоги «Перераспределено N · Не разместились 54 ч (M задач)».
- Тело — список `TASK-102 · 16 ч → Анна Смирнова`; непоместившиеся задачи отдельным красноватым блоком «Без ответственного».
- Footer: plan-cancel (secondary), plan-apply (primary); apply — единственная точка, меняющая state.
- reset-demo — вне модалки, в служебной строке внизу страницы.
- Длинные подписанные кнопки (propose-plan, plan-apply, plan-cancel, reset-demo) — в ряд с flex-wrap или стопкой; запрещены четыре колонки кнопок рядом с боковой панелью и обрезка подписей.

## 6. Поведение по ширинам (тестиды и показатели сохраняются везде)
- 1280: container 1200+; доска — 3 равные колонки; метрики 4×1; employees — полная таблица; модалки 560 px.
- 1100: container 1080; доска 3 колонки; метрики 4×1 или 2×2; таблица сотрудников остаётся; toolbar в одну строку.
- 768: без горизонтального переполнения: колонки доски — на всю ширину вертикально (todo→doing→done, min-height 120 px); метрики 2×2; таблица → карточки с блоками «Загрузка» и «Прогресс» друг под другом; toolbar и week-nav — перенос на 2 строки; search/filter по 100%.
- 390: всё в одну колонку; заголовок и недельная навигация — отдельной строкой; кнопки new-task/propose-plan/apply/cancel — полноширинные стопкой; edit/delete в карточке — с текстом, зона нажатия ≥44 px; длинные слова/числа переносятся (overflow-wrap); таблицы запрещены; оба показателя каждого сотрудника читаются без скролла.

## 7. Передача разработчику
- Только локальный dist/vendor/tabler (1.6.1); палитра: акцент #206bc4, текст #182433, фон #f6f7f9, границы #e6e8ec, ошибка #d63939, done #2fb344; без внешних ресурсов.
- Точные data-testid из INTERFACES; статусная модель drag-and-drop = модель select task-status.
- Форматы: проценты Math.round, «133%»; null-percent → «—»; перегрузка вида «+8 ч» только при >0 (ANALYSIS §3.3, §4).
- Клавиатура: tabbed-порядок форма→ошибки→save; aria-live на task-error и plan-preview итоги.
- После реализации — DOM-ревью в браузере (getComputedStyle, проверка переполнения на 390/768/1100/1280), скриншоты в artifacts/, без заявлений о визуальном чтении.
