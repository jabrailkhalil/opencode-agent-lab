# DESIGN-PLAN: «Поток» — план команды

Задание разработчику. Файлы: `dist/index.html`, `styles.css`, `app.js`, `domain.js`. Только Tabler-классы из `vendor/tabler/tabler.min.css` (`<link>` на него первым) + небольшой `styles.css` для доработок. Без сборщика, без CDN, без внешних шрифтов/иконок (иконки — Unicode/inline SVG). `<html lang="ru">`, `<meta viewport width=device-width, initial-scale=1>`.

## 1. Токены (styles.css, `:root`)
- `--tblr-primary:#206bc4` (акцент), текст `#182433`, фон страницы `#f6f7f9`, граница `#e6e8ec`, ошибка/перегрузка `#d63939`, готово `#2fb344`, предупреждение (загрузка 90–100%) `#f76707`.
- Цвета сотрудников брать из `employee.color` (аватар-инициалы 32px, круг, белый текст).
- Радиус 4px, тени только `shadow-sm` у карточек. Базовый шрифт Tabler, 14px. Минимальный размер интерактива 36px высоты (на ≤768 — 40px).
- `*{box-sizing:border-box}`, `html,body{overflow-x:hidden}` не использовать как лекарство: переполнения устранять вёрстками (`min-width:0`, `overflow-wrap:anywhere` для названий/описаний).

`<div class="page" data-testid="app">` (ставить testid, когда состояние загружено и первый рендер завершён)
1. **Навигация (светлая)** `header.navbar.navbar-expand-md` белый фон, нижняя граница: логотип-текст «Поток», подзаголовок «Трекер задач и загрузка». Справа: `reset-demo` («Восстановить пример», `btn btn-outline-secondary`).
2. **Шапка страницы** `page-header`: h1 «План команды»; справа блок недели: `prev-week` (`‹ Пред.`), `current-week` (текст «28 сен – 4 окт 2026», `<time datetime="2026-09-28">`, дополнительно мелким «неделя с 2026-09-28»), `next-week` (`След. ›`); кнопка `new-task` («Новая задача», primary).
3. **Недельные метрики** (`row row-cards`, 4 карточки `col-6 col-lg-3`): «Задач на неделе» (9), «Всего часов» (80), «Активно» (7 задач / 70 ч), «Выполнено» (часов и % от всех). Значения по задачам недели, не зависят от поиска/фильтра. testid: `metric-tasks`, `metric-hours`, `metric-active`, `metric-done`.
4. **Панель управления** `card` с `card-body`: поле `search` (`type=search`, label «Поиск», placeholder «Название или описание»), `filter-assignee` (label «Ответственный», пункты «Все», 4 сотрудника, «Без ответственного» — для него value `""` невозможно, т.к. пустое = все; поэтому «Без ответственного» не включать в фильтр), переключатель представлений `btn-group` `view-board` («Доска») / `view-employees` («По сотрудникам»), `aria-pressed`/класс `active`; `propose-plan` («Предложить распределение», `btn-outline-primary`). Счётчик найденных «Найдено: N из M» (`results-count`).
5. **Панель предпросмотра** `plan-preview` (скрыта `hidden`, пока нет плана): `card` с акцентной левой границей 4px primary, заголовок «Предложенное распределение», таблица «Задача | Было | Станет | Часы», итоги: «Назначено N задач, не помещается M ч (остаются без ответственного)», строка «После применения: Анна 24/24 …» для 4 сотрудников. Кнопки `plan-apply` («Применить», primary) и `plan-cancel` («Отмена»). Текст «Это предпросмотр — план не изменён». Блок вставляется над основным представлением, не поверх.
6. **Загрузка команды** (всегда видна, в обоих представлениях) `team-load` — 4 строки/карточки `employee-anna|dmitry|maria|ilya`, см. §3.
7. **Основное представление**: либо `board` (доска), либо `employees-view` (задачи по сотрудникам); неактивное — `hidden`, не удалять из DOM по умолчанию не требуется, но `data-testid` должен быть только у видимого.
8. **Форма задачи** — модальное окно Tabler (`modal modal-blur` + `modal-dialog`), `task-form`; открывается `new-task`/`edit-*`. Фокус-ловушка, Esc = `task-cancel`, возврат фокуса на кнопку-источник.
9. **Подтверждение** (удаление, восстановление примера) — малое модальное окно `modal-sm` с кнопками «Подтвердить»/«Отмена» (`confirm-ok`, `confirm-cancel`); текст конкретный: «Удалить задачу TASK-101 «…»?» / «Заменить все данные учебным примером?».
10. Live-регион `<div role="status" aria-live="polite" data-testid="toast">` для «Задача сохранена», «План применён», «Данные повреждены — загружен пример».

## 3. Загрузка и прогресс сотрудников (критично — не скрывать ни на какой ширине)
Карточка/строка `employee-{id}` содержит:
- аватар-инициалы, имя, роль;
- `load-{id}`: подпись «Загрузка» + «32 / 24 ч · 133%» (активные часы / доступные; процент `Math.round`, при доступности 0 — «—», без NaN/Infinity); при перегрузке отдельный бейдж `bg-red-lt`: «Перегрузка +8 ч» (число и подпись, не только цвет); без перегрузки — «Свободно N ч» (`bg-green-lt`), при точном 100% «Загружено полностью»;
- полоса загрузки `progress` (`progress-sm`), ширина `min(percent,100)%`, цвет: ≤89% primary, 90–100% оранжевый, >100% красный; для 0 доступности — серая пустая;
- `progress-{id}`: подпись «Выполнено» + «43% · 6 из 14 ч» (done/всех назначенных часов недели; при 0 часов — «0% · 0 из 0 ч»); полоса зелёная `#2fb344`;
- `capacity-{id}`: `input type=number min=0 max=168 step=1`, label «Доступность, ч/нед», сохранение на `change` и `blur`; невалидное значение (пусто, <0, >168, не число) — inline-ошибка `capacity-error-{id}` под полем, `is-invalid`, значение в хранилище не меняется, поле не сбрасывается до исправления.
Ожидаемые значения seed: Анна 32/24 133% +8; Дмитрий 14/32 44%; Мария 8/24 33%, прогресс 43%; Илья 12/24 50%, прогресс 25%.
Раскладка: ≥1100 — 4 колонки в ряд (`col-xl-3`); 768–1099 — 2×2; <768 — одна колонка, компактные карточки. Метрики внутри карточки: подпись над значением, не в `title`.

## 4. Доска (`board`)
- 3 колонки `column-todo|doing|done`, заголовки «Новая», «В работе», «Готово» + счётчик задач и сумма часов в колонке (`badge`). Колонка — drop-зона (`dragover` → подсветка пунктирной рамкой primary), min-height 160px, пустое состояние «Нет задач — перетащите сюда».
- Раскладка: ≥768 — 3 колонки `col-md-4`; <768 — колонки стопкой, каждая на полную ширину (без горизонтального скролла доски).
- Карточка `task-{ID}` (`card card-sm`, `draggable="true"`, `data-task-id`): id мелко-серым, название (жирное, переносится), описание (2 строки `-webkit-line-clamp`, полный текст в DOM), нижняя строка: бейдж часов «16 ч», аватар/имя ответственного или «Без ответственного» (серый), бейдж статуса цветом (todo серый, doing синий, done зелёный). Выполненные: название зачёркнуто не нужно, но приглушённый фон и галочка «✓».
- Кнопки `edit-{ID}` («Изменить»), `delete-{ID}` («Удалить», `btn-ghost-danger`), текстовые подписи, `aria-label` с ID. Не только иконки.
- Drag: `dragstart` ставит `dataTransfer` с id, класс `dragging` (opacity .5); `drop` меняет статус, сохраняет, перерисовывает, toast «TASK-… → В работе». Клавиатурная альтернатива — смена статуса через форму (edit).
- Поиск/фильтр скрывают карточки (не удаляя данные); если колонка пуста из-за фильтра — «Нет подходящих задач». Общий пустой результат: `empty-results` «Ничего не найдено. Сбросить поиск», кнопка сброса.

## 5. Представление «По сотрудникам» (`employees-view`)
Для каждого сотрудника + «Без ответственного» — секция `card`: заголовок (аватар, имя, нагрузка и прогресс коротко), ниже таблица `table table-vlite` задач: ID, Название, Статус, Часы, Действия (`edit-*`, `delete-*`). Те же testid карточек: у видимого представления только один элемент с `task-{ID}` (строка `<tr data-testid="task-TASK-101">`). На <768 таблица превращается в стопку карточек (`display:block` на tr/td, подписи через `data-label`), без горизонтального скролла. Нет задач — «Нет задач на эту неделю».

## 6. Форма задачи (`task-form`)
Заголовок «Новая задача» / «Изменить TASK-101». Поля с видимыми `<label for>`:
| testid | элемент | label | заметки |
|---|---|---|---|
| `task-title` | input text | Название * | `maxlength` НЕ ставить (проверка прикладная); без `required` блокирующего: форма `novalidate` |
| `task-description` | textarea rows=3 | Описание | счётчик «N / 1000» |
| `task-assignee` | select | Ответственный | `""` = «Без ответственного» + 4 `employee.id` |
| `task-hours` | input type=number step=0.5 min=0.5 max=168 | Оценка, ч | без `novalidate` браузер блокирует 0,7 — поэтому `novalidate` обязателен |
| `task-status` | select | Статус | todo/doing/done: Новая/В работе/Готово |
| `task-week` | input type=date | Неделя (понедельник) | по умолчанию текущая неделя |
Кнопки: `task-save` («Сохранить», primary), `task-cancel` («Отмена»). Ошибки: `task-error` — `alert alert-danger role="alert"` внутри формы в верху тела (перед полями), текст конкретный («Название: от 1 до 140 символов после удаления пробелов», «Оценка: от 0,5 до 168 с шагом 0,5», «Неделя должна начинаться с понедельника»); для нескольких ошибок — список. Дополнительно у проблемного поля `is-invalid` + `invalid-feedback`. При ошибке форма остаётся открытой, значения не сбрасываются, фокус на первом невалидном поле, `aria-invalid="true"`. Элемент `task-error` отсутствует/скрыт, пока ошибок нет. Успех — закрыть форму, toast. Edit предзаполняет значения; редактирование не меняет ID.
Ширина модалки: 520px на ≥768, на 390 — почти на весь экран (margin 8px), `modal-dialog-scrollable`.

## 7. Недели и состояния
- `current-week` обновляется при prev/next (±7 дней, расчёт без часового пояса). Метрики, доска, нагрузка и `capacity-*` показывают данные выбранной недели. Пустая неделя: метрики 0, прогресс «0% · 0 из 0 ч», НЕ NaN; на доске пустые колонки; подсказка «На этой неделе задач нет. Создайте первую».
- Новая задача по умолчанию получает неделю, отображаемую сейчас.
- Предпросмотр плана привязан к неделе; смена недели, редактирование задач или capacity закрывает его (сбрасывает) с toast «Предпросмотр сброшен».
- Пока предпросмотр открыт: `propose-plan` disabled; задачи не меняются; в строке предпросмотра перегрузка не показана (план её исключает). Если активных задач нет — `plan-preview` не открывается, toast «Нет активных задач для распределения».
- `reset-demo` → подтверждение → seed, неделя 2026-09-28, фильтры сброшены.
- Повреждённый localStorage: парсинг в try/catch, `isValidState` → иначе seed + информационная плашка `storage-notice` (`alert-warning`, закрываемая) «Сохранённые данные повреждены, загружен учебный пример». Приложение не падает.
- Загрузка: до первого рендера `app` без testid не нужен; пустой `aria-busy`.

## 8. Адаптация (проверять 390 / 768 / 1100 / 1280)
- Контейнер `container-xl`, внутренние отступы 12px на <768, 16px+ на ≥768.
- Шапка страницы: на <768 заголовок над блоком недели, `new-task` на всю ширину; блок недели — flex, `current-week` растягивается, кнопки prev/next 44px.
- Панель управления: ≥1100 — одна строка (поиск 4 / фильтр 3 / переключатель 3 / предложить 2 колонки); 768–1099 — две строки; <768 — все контролы на всю ширину, переключатель двумя равными кнопками.
- Метрики: ≥992 — 4 в ряд, <992 — 2×2, на 390 — 2×2 компактные (значение 20px).
- `scrollWidth === clientWidth` на `documentElement` на всех четырёх ширинах. Длинное название (140 символов без пробелов) переносится (`overflow-wrap:anywhere`), не расширяет карточку/таблицу.
- Порядок на 390: навигация → заголовок/неделя → метрики → загрузка команды (4 карточки) → управление → представление.  Загрузка команды располагается выше управляющей панели на всех ширинах, чтобы показатели были без прокрутки поиска; дизайн-порядок п.4/п.6 меняется на: метрики → загрузка команды → панель управления → предпросмотр → представление.

## 9. Доступность
Все контролы — реальные `button`/`input`/`select` с `<label>`; видимый фокус (`outline:2px solid #206bc4; outline-offset:2px`). Tab-порядок = визуальный. Модалки `role="dialog" aria-modal aria-labelledby`. Переключатель представлений — `aria-pressed`. Статус не только цветом (текст в бейджах). Контраст текста ≥4.5:1 (серый вторичный текст не светлее `#667382`). `prefers-reduced-motion` — убрать анимации.

## 11. Критерии DOM-ревью
1. Все testid из §10 найдены; `load-anna` = «32 / 24 ч · 133%» и «+8 ч»; `progress-maria` 43%, `progress-ilya` 25%.
2. `document.documentElement.scrollWidth <= innerWidth` на 390/768/1100/1280; 4 `progress-*` и 4 `load-*` имеют ненулевой `getBoundingClientRect` и пересекают viewport по ширине.
3. Размеры интерактива ≥36px по высоте (≥40 на ≤768); тексты не обрезаются без доступа.
4. Ошибка формы: `task-error` внутри `task-form`, видим, значения полей сохранены.
5. Нет NaN/Infinity/undefined/null в `body.innerText` на пустой неделе и при нулевой доступности.
6. Все `input/select/textarea` имеют label; консоль без ошибок.
7. Скриншоты 4 ширин + форма с ошибкой + предпросмотр сохранить в `reports/screenshots/`.
