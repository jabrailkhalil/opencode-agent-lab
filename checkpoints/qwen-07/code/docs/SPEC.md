# Исходная постановка: полный трекер задач и планировщик нагрузки

Нужно с нуля написать работающий локальный веб-сервис «Поток». Он объединяет трекер задач и недельный планировщик загрузки сотрудников. Это первый полный замер, все роли используют Qwen3 Coder Next. Код предыдущего приложения использовать нельзя: в dist заранее есть только локальный CSS Tabler.

## Полный объём

1. Создание, просмотр, редактирование и удаление задач. Поля: название, описание, ответственный или «Без ответственного», оценка в часах, статус, неделя.
2. Статусы todo/doing/done: «Новая», «В работе», «Готово». Доска из трёх колонок с drag-and-drop и сменой статуса через форму.
3. Второе представление — задачи по сотрудникам; переключение туда и обратно. Оба представления используют одни данные.
4. Поиск по названию/описанию и фильтр по ответственному; поиск не пересчитывает недельную нагрузку только по найденным задачам.
5. Переходы предыдущая/следующая неделя. Начальная неделя 2026-09-28. Задачи и доступность разных недель независимы.
6. Для четырёх сотрудников — изменение недельной доступности от 0 до 168 часов. Нагрузка считается по незавершённым задачам. Выполненные учитываются в прогрессе, но не занимают доступность.
7. Загрузка: активные часы / доступные часы, округлённый процент и перегрузка в часах. Прогресс: выполненные часы / все назначенные часы текущей недели. Нулевой знаменатель не даёт NaN/Infinity.
8. Предложить распределение активных задач с предпросмотром, отменой и явным применением человеком. Предпросмотр не изменяет исходный план. Нельзя назначать сверх доступности; не помещающиеся задачи остаются без ответственного. Выполненные задачи, чужие недели, количество задач и общий объём часов сохраняются.
9. localStorage: изменения сохраняются после перезагрузки. Повреждённые данные обрабатываются без падения приложения. Восстановление учебного примера — после подтверждения.
10. Проверка формы: название после trim 1–140 символов; описание до 1000; оценка 0,5–168 с шагом 0,5; существующий ответственный или null; допустимый статус; дата недели — понедельник. Ошибка видна в открытой форме, значения не сбрасываются.
11. Полный адаптивный UI: 390, 768, 1100, 1280 px; никакого горизонтального переполнения, нагрузка и прогресс каждого сотрудника доступны. Подписанные формы, управление клавиатурой, одинаковый стиль Tabler.

Начальные вымышленные данные — docs/seed-state.json: 9 задач, 80 часов всего, 7 активных задач / 70 активных часов. Анна: 32/24, 133%, +8 ч. Мария: прогресс 43%, Илья: 25%. Эти значения должны реально считаться из данных.

Работающий сервис: http://127.0.0.1:4190/. Уже запущен статический сервер; зависимости готовы. Нужно создать dist/index.html, styles.css, app.js, domain.js. Не нужен npm install, сборщик, backend, облачная публикация или вход пользователей. Прочитайте docs/DOMAIN-CONTRACT.md, docs/DESIGN-REFERENCE.md и docs/QA-CHECKLIST.md.

Готово означает: весь перечисленный функционал реализован, независимые приёмочные проверки и настоящие браузерные действия выполнены, артефакты сохранены. Частичный прототип не объявлять завершённым.
