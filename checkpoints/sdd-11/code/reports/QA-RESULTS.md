## Реальные ошибки

### B1 (средняя). `isValidState` принимает `hours` строкой
Требование: spec «Хранение» — `isValidState` отклоняет неверные поля задач. Сейчас `validateTask` внутри допускает числовую строку и результат отбрасывается, поэтому в состояние попадает строка.
Воспроизведение: `s = seedState(); s.tasks[0].hours = '16'; isValidState(s)` → `true` (ожидалось `false`). Тест: `agent-qa` «isValidState отклоняет hours-строку».
Последствие (по коду, в браузере не запускалось): в `localStorage` кладётся такое состояние → при загрузке уведомления нет, а `loadFor` складывает через `reduce(s + t.hours)`, получается конкатенация строк («01616»), нагрузка и проценты искажены.
Где: `dist/domain.js:97-123` (строка 119 вызывает `validateTask`, но не проверяет `typeof t.hours === 'number'` и не использует нормализованную копию).

### B2 (низкая, безопасность/устойчивость). `isValidState` не ограничивает формат `id`
Воспроизведение: `s.tasks[0].id = 'x" onmouseover="1'; isValidState(s)` → `true`. Тест: `agent-qa` «isValidState отклоняет id задачи с кавычкой».
В `app.js` id подставляется без `esc()` в атрибуты (`data-id`, `data-testid` — стр. 122, 127, 128; сотрудники — `id`/`data-testid` стр. 65-80) → возможна инъекция атрибутов при подмене `localStorage` (только самоатака в своём браузере). Исправление: требовать `^TASK-\d+$` для задач и безопасный `^[a-z0-9_-]+$` для сотрудников, плюс `esc()` в атрибутах.

### B3 (низкая). `validateTask` принимает `'0x10'` и `'1e1'` как оценку
Воспроизведение: `validateTask({title:'a',hours:'0x10',...})` → `hours: 16`; `'1e1'` → `10`. Тест: `agent-qa` «шестнадцатеричная и экспоненциальная запись отклоняются».
Причина: `Number(str.replace(',', '.'))` (стр. 87). Спецификация говорит «числовая строка из формы»; в форму можно ввести `0x10` в text-поле `task-hours` — задача создастся на 16 ч. Исправление: проверять строку регулярным выражением `^\d+([.,]\d+)?$`.

### B4 (низкая, отклонение от спецификации; по коду). Пустая неделя без колонок доски
Требование: «Доска `board` SHALL иметь колонки `column-todo/doing/done`».
Воспроизведение (по коду, не в браузере): открыть `next-week` на seed (задач нет) → `renderBoard` при `all.length === 0` (стр. 136) рисует только `empty-state`; `column-todo/doing/done` в DOM отсутствуют. Задачу на пустую неделю нельзя перетащить, автоматический тест, ищущий `column-*`, не найдёт элементы. Исправление: рисовать колонки всегда, а пустое состояние — внутри/над ними.
