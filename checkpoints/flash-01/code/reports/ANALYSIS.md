# ANALYSIS — трекер «Поток»: формулы и неоднозначности

Вход: docs/BRIEF.md, docs/INTERFACES.md, docs/seed-state.json (сверка с tests/acceptance.test.mjs, чтение без изменений).

## 1. Проверенные формулы (сошлись с брифом на seed)

Для сотрудника `e` и недели `w`:

- `tasks` — все задачи с `assignee=e.id и week=w`, включая done (тест 2: `tasks.length=2` после перевода TASK-101 в done).
- `active` — подмножество todo/doing.
- `hours` (нагрузка) = Σ часов `active`. Выполненные доступность **не занимают**.
- `capacity` = `e.capacities[w]` при наличии, иначе `e.capacity`.
- `totalHours` = Σ часов **всех** назначенных задач недели (todo+doing+done).
- `doneHours` = Σ часов done-задач недели.
- `overload` = max(0, hours − capacity). При capacity=0 и hours=32 → overload=32 (тест 6).
- `percent` = capacity === 0 ? **null** : Math.round(hours / capacity · 100).
- `progress` = totalHours === 0 ? **0** : Math.round(doneHours / totalHours · 100).
- NaN/Infinity невозможны: оба нулевых знаменателя обработаны (null / 0).

Контрольные значения на seed (неделя 2026-09-28, всего 9 задач / 80 ч, активных 7 / 70 ч — сходятся):

| Сотрудник | Активные ч | Доступность | percent | overload | totalHours | doneHours | progress |
|---|---|---|---|---|---|---|---|
| Анна | 32 | 24 | 133 | 8 | 32 | 0 | 0 |
| Дмитрий | 14 | 32 | 44 | 0 | 14 | 0 | 0 |
| Мария | 8 | 24 | 33 | 0 | 14 | 6 | **43** |
| Илья | 12 | 24 | 50 | 0 | 16 | 4 | **25** |

Тест 2 подтверждает прогресс Анны при done-переводе: 16/32 = 50%.

## 2. Неоднозначности и принятые решения

1. **Границы percent/progress.** Проценты целые через Math.round (контракт); дроби допустимы только в часах (шаг 0.5). UI: целое число %; часы показывать как есть (возможны `.5`), перегрузка с знаком «+».
2. **capacity = 0.** `percent = null` — не «0%». UI обязан показать заглушку («—» / «нет доступности»), иначе пустое место читается как 0%. `progress` при 0 назначенных = 0 (показывается как 0%, это осмысленно: ничего не сделано).
3. **Область proposePlan.** Тест 3 (unassignedHours=54 = 70−16 при anna/maria/ilya cap 0, dmitry cap 16) доказывает: перераспределяются **все активные задачи недели**, включая уже назначенные; при нехватке доступности задача становится `assignee=null`. Решения по выполненным задачам и чужим неделям не принимаются (тест 5: TASK-999 другой недели не меняется).
4. **Алгоритм (свободный выбор, предложен разработчику).** Детерминированный greedy: активные задачи недели сортируются по часам убывание (при равенстве — по id), каждая назначается первому сотруднику в порядке массива employees, у которого `текущие активные часы + задача ≤ capacity`; иначе → без ответственного. Проверено на обоих тестах: seed → перегрузки нет, 0 неназначенных; cap 16 у Дмитрия → ровно 54 ч unassigned. `unassignedHours` = Σ часов активных задач недели без ответственного после применения плана.
5. **assignments в плане.** Включать только задачи, чей assignee меняется (в том числе перевод в null) — предпросмотр показывает diff; applyPlan применяет их к копии состояния (мутации входа запрещены тестом 3).
6. **Изменение доступности через UI.** Пишет `capacities[текущая неделя]` (переопределение), базовое `capacity` seed не трогать — иначе «независимость недель» (бриф п.5) ломается. Диапазон 0–168.
7. **Поиск/фильтр.** Нагрузку и прогресс всегда считать по всем задачам недели из полного состояния; фильтр влияет только на список карточек (бриф п.4).
8. **Фильтр «Без ответственного».** Контракт задаёт в filter-assignee только employee.id и пустое = все. Дополнительное значение не добавлять (риск рассинхрона с фиксированными browser-проверками); не назначенные видны в доске как отдельная зона/пометка.
9. **Повреждённый localStorage.** isValidState=false → не падать, начать с валидного «чистого» состояния: employees из seed (справочник UI), `tasks: []`, `nextId: 110`, текущая неделя DEMO_WEEK; показать баннер с кнопкой reset-demo (восстановление примера только после подтверждения, бриф п.9).
10. **validateTask.** Вход не мутировать, возвращать копию с trim. Название 1–140 после trim (пробелы = пусто, тест 7), описание ≤ 1000, часы 0.5–168 кратно 0.5 (0, −1, 0.7, 169, NaN, Infinity — ошибка), assignee — существующий id или null, статус из todo/doing/done, week — понедельник в формате YYYY-MM-DD (помогает monday()). Ошибки — в открытой форме без сброса значений.
11. **monday() без часовых поясов.** Работать со строкой/UTC, не с локальным Date-парсингом «YYYY-MM-DD» (сдвиг зоны делает 2026-09-28 воскресеньем при локальном разборе). 2026-09-28 — понедельник, стартовая неделя верна.
12. **Клавиатурная альтернатива drag-and-drop.** Смена статуса через форму (edit-кнопка → task-status) покрывает требование «управление клавиатурой»; D&D — only mouse-путь.

## 3. Заметки для дизайнера

- Метрики на строке/карточке сотрудника: загрузка «32 / 24 ч · 133% · +8 ч перегруз» и прогресс «done/total ч · %», testid `load-<id>`, `progress-<id>`; при percent=null — «—», перегрузка визуально (красный бейдж Tabler), но не единственная подсветка (доступность imho дублировать текстом).
- Значения должны читаться на 390 px без горизонтального скролла: узкая карточка → метрики списком, широкая → строкой; поле `capacity-<id>` — number input 0–168 с шагом, подпись «доступность недели».
- Переключатель представлений board/employees — один и тот же dataset; недельная шапка с `current-week`, prev-week/next-week.
- Предпросмотр плана: сравнение «было → стало» по сотрудникам (часы до/после, кто что получил), неназначенные часы (`unassignedHours`) — явным блоком; кнопки plan-apply / plan-cancel, apply только по клику человека.
- Ошибки формы — инлайн в открытой форме (`task-error`), введённые значения сохраняются.
- Стиль — только локальный Tabler (dist/vendor/tabler), без внешних ресурсов.

## 4. Фиксация для domain.js (экспорт-контракт)

`DEMO_WEEK='2026-09-28'`, `seedState()` (свежая копия seed на каждый вызов), `monday(date)`, `loadFor(state, employeeId, week)`, `validateTask(task, employees)`, `proposePlan(state, week)`, `applyPlan(state, plan)`, `isValidState(state)` (дубли id / лишние-кривые поля / nextId<110 → false).

Все расчёты сверены арифметически с seed и текстом девяти зафиксированных тестов; расхождений нет.
