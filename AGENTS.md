# Настройка комплекта на новом ноутбуке

Это открытый комплект материалов демонстрации для ВТБ: пять сохранённых прогонов, PDF-инструкция, конфигурации OpenCode, код и проверяемые чекпоинты. Инструкции для конечного пользователя находятся в README.md и docs/LAPTOP-SETUP.md.

## Задача агента при переносе

1. Определи ОС, архитектуру процессора, версии Node.js и npm. Проверенный вариант — Windows 10/11 и Node.js 22.14+ или 24 LTS. Для иной ОС сначала оцени совместимость, не объявляй запуск проверенным заранее.
2. Используй текущий каталог клона/распакованного архива. Не переноси пути, имена профилей пользователя или рабочие сессии с другого компьютера.
3. Выполни npm ci. Если Node.js отсутствует, установи его из официального источника в пределах разрешений пользователя. Предварительная установка OpenCode не требуется.
4. Выполни npm run check и npm test. Контрольные суммы снимков должны совпасть.
5. Выполни npm run doctor -- --json. Если порты заняты, сначала установи владельца. Не останавливай чужие процессы ради освобождения порта.
6. Запусти npm start -- --open. Ожидается главная страница с PDF и пятью результатами, два пульта и двойное окно OpenCode.
7. Проверь PDF по /guide.pdf, пять приложений с главного экрана, таблицу /comparison#conclusion и оба окна OpenCode. Нажми «Вставить оба промпта» и убедись, что отправка доступна.
8. Для проверки полного перехода используй npm run smoke: он вызывает только локальную запись и продвигает левую ветку на один чекпоинт. Затем npm stop и npm start -- --open возвращают стенд к чистому старту.
9. Передай пользователю фактические результаты проверок, основной адрес http://127.0.0.1:4201/welcome, способ запуска/остановки и найденные ограничения.

## Границы работы

- По умолчанию только запись: не подключай платный API и не меняй режим без явного запроса пользователя.
- Нужный OpenCode и SDK закреплены в package-lock.json. Не обновляй версии автоматически: автоподстановка привязана к этому интерфейсу.
- Не редактируй checkpoints/ для устранения проблемы установки. Это исходные данные опыта; изменения снимков нарушат SHA-256.
- Изменяемые рабочие папки и логи находятся в .runtime/. Предыдущие рабочие папки сохраняются перед сбросом.
- Публикуй только материалы комплекта. Личные памятки, переписки, записи встреч, API-ключи, .runtime/ и node_modules/ в репозиторий не входят.
- Проверки для изменений: npm run check, npm test и соответствующая проверка в браузере. Не утверждай, что API-генерация или браузерный сценарий выполнены, если они не запускались.
- Windows проверена. macOS/Linux требуют отдельной проверки лаунчера и нужной сборки OpenCode; укажи это, если перенос выполняется туда.
